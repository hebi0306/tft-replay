# 챔피언 종류 인식 — 2026-10-31

최신 참조는 모든 기존 경기 시각 검토를 거친 65종/303장입니다. 최신 비교와 한계는 `IDENTITY_ALL_GAMES.md`를 확인하세요. 아래는 과거 변경 이력입니다.

최신 구현은 픽셀 비교 뒤 특징점 배치 검증을 추가합니다. 최신 수치와 한계는 `IDENTITY_FEATURE_MATCHING.md`를 참조하세요. 아래는 이전 변경 이력입니다.

## 최신 안정성 보완: 작은 픽셀 차이 완화

챔피언 전용 정렬 비교의 48×48 입력과 참조에 3×3 Gaussian smoothing을 적용했습니다. 작은 픽셀 변화의 영향을 줄이며, 임계값 .85와 다른 후보와의 차이 .15는 유지합니다. 아이템/성급/빈 벤치에는 적용하지 않습니다. 5×5도 비교했지만 추가 이득이 없어 3×3만 적용했습니다. 비슷한 다른 클래스 참조 12쌍을 시각 점검했고 추가로 확정할 수 있는 라벨 오류는 찾지 못했습니다.

경기 단위 제외 검증: 알려진 종류 96표본에서 확정 정답 14→21, 미확인 75, 오답 0. 참조에 없는 종류 145표본과 배경/모루/구슬 17개는 모두 거부했습니다. 같은 평가 자료로 방법을 선택했으므로 독립적인 최종 정확도가 아닙니다.

밝기 0.85배/1.1배 및 작은 노이즈를 추가한 경기 분리 비교 723개에서 정답 42→63, 오답 0→0, 미확인 681→660. 합성 변형 검증이며 새로운 게임/자세/스킨의 검증이 아닙니다. CPU 비교당 약 23.3ms였습니다. Python 테스트 43개와 Stage/HP/Gold/Level/스크린샷 저장·조회 통합 검사 통과. 모델/참조 라벨/원본 녹화는 수정하지 않았습니다. 설치파일 미생성.

결과: `capture-build/identity-smoothed-validation.json`, `identity-smoothing-stress.json`, `identity-smoothing-integration.log`. 코드: `capture/reference_matcher.py`, `test_board_analysis.py`. 종류 인식이 여전히 미확인 위주라는 한계가 남아 있으며, 65종 안정 인식을 완료한 것으로 표시하지 않습니다.


최신 참조는 사용자 이름 지정 첨부 5종까지 반영한 241장/65종입니다. 첨부 파일 경로가 없어 기존 녹화에서 시각적으로 같은 몸체를 재추출했으며 자세한 출처는 IDENTITY_ROSTER_COVERAGE.md에 기록했습니다. 케넨으로 잘못 확장했던 아무무 1장을 수정하고 아이번·장로 드래곤 몸체 참조를 추가했습니다. 상세 근거와 남은 6종은 `IDENTITY_ROSTER_COVERAGE.md`를 확인하세요. 아래 수치는 각 변경 당시의 이력입니다.

## 크기 오차 보정 추가 (v4)

같은 유닛의 탐지 bbox 크기가 달라지는 경우를 위해 챔피언 중앙 참조를 36/40/44픽셀 크기로 미리 준비해 비교합니다. 임계값 .85와 후보 간 차이 .15는 유지합니다. 좌우 반전은 검증상 이득이 없어 채택하지 않았습니다. 기존 사용자 라벨 및 원본 캡처는 수정하지 않습니다.

실제 matcher의 경기 분리 검증: 알려진 종류 90표본 중 14개 확정/14개 정답, 76개 미확인(이전 13개 정답). 미등록 종류 140표본과 음성 표본 17개는 전부 거부했습니다. 평균 비교 시간은 약 21.4ms로 이전 7.4ms보다 증가했습니다. 분석은 기존대로 라운드 저장 시 별도 작업에서 실행합니다. 이미 반복해서 살펴본 자료이므로 독립적인 최종 정확도로 해석할 수 없습니다.

테스트 42개 통과. 평가: `capture-build/identity-scale-validation.json`, 재현: `capture-build/verify_identity_scale.py`. 전체 라운드 실행 결과: `capture-build/identity-v4-runtime/`. 기존 라운드 원본 DB는 덮어쓰지 않습니다. 앱을 완전히 종료 후 `npm start`로 재실행하면 이후 분석에 적용됩니다. 종류 인식 범위는 여전히 제한적이고 성급/아이템은 미완성입니다.


## 위치 오차 보정 추가 (v3)

챔피언 참조 비교에만 작은 평행 이동 보정을 적용했습니다. 48×48 정규화 이미지의 중앙 40×40 참조를 ±4픽셀 범위에서 비교합니다. 회전/좌우 반전이나 임계값 완화는 하지 않습니다. 단색 참조는 제외하고, 두 종류가 비슷하면 여전히 미확인으로 반환합니다. 아이템·별·빈 벤치 비교 방식은 변경하지 않았습니다.

실제 런타임 matcher로 동일 경기의 참조를 전부 제외해 평가했습니다. 알려진 종류 90개 중 13개가 확인됐고 모두 라벨과 일치했습니다(이전 8개). 나머지 77개는 미확인입니다. 처음 보는 종류 140개 및 배경/모루/구슬 17개는 모두 거부했습니다. 비교당 평균 약 7.4ms였습니다. 이 자료를 방법 선택에 사용했으므로 독립적인 일반화 정확도는 아닙니다.

회귀 테스트 41개 통과. 결과: `capture-build/identity-alignment-validation.json`. 재현: `capture-build/verify_identity_alignment.py`. 전체 저장 라운드 재분석은 원본 DB를 변경하지 않고 `capture-build/identity-v3-runtime/`에 저장합니다. 아래 v2 내용과 통계는 이전 변경의 이력입니다.


## 현재 적용

실패했던 신경망 분류기는 계속 비활성 상태입니다. 기존 참조 이미지 비교 방식을 보강해, 충분히 비슷하고 다른 후보와 차이가 큰 경우에만 championId를 반환합니다. 나머지는 null입니다. 위치 모델 v6와 성급/아이템 코드는 유지합니다.

- 세 번째 기존 경기에서 이전 사용자 확인 이미지와 확실히 대조되는 8종 27개 몸체 crop을 추가했습니다. 모호한 스킨/자세 및 글자에 가린 대상은 제외했습니다. 새 라벨은 사용자 직접 확인이 아니라 assistant 시각 대조임을 기록했습니다.
- 참조 총 56종/230장. 기존 라벨을 덮어쓰지 않고 `expanded.json`, `third-match.json`으로 확장했습니다.
- 벤치 이름 인식 입력을 슬롯 전체에서 탐지된 몸체 bbox로 변경했습니다. 모델이 유닛을 탐지하지 않은 슬롯은 이미지 유사도만으로 유닛/이름을 만들지 않습니다.
- 챔피언만 유사도 0.85 이상, 다른 종류와 차이 0.15 이상일 때 확정합니다. 아이템/별/빈 벤치의 기존 임계값 0.92/0.06은 유지합니다. 이 유사도는 확률이 아닙니다.
- ONNX bbox를 원래 영역으로 되돌릴 때 합산 소수점 오차로 0.0000x픽셀 벗어나는 문제를 출력 경계에서 수정했습니다. 엄격한 crop 검증은 유지합니다. 같은 회귀 표본 100개에서 이전 코드가 11번 범위를 벗어났고 수정 후 모두 통과했습니다.

## 평가 범위와 한계

동일 경기의 모든 이미지를 참조에서 제외하는 방식으로 평가했습니다. 다른 경기에 동일 종류가 존재하는 90표본 중 8개가 임계값을 통과했고 모두 맞았습니다. 처음 보는 종류인 140표본은 모두 미확인으로 거부했습니다. 알려진 종류 82개도 미확인으로 남습니다. 임계값 선택에 사용한 작은 검증 집합이므로 독립적인 최종 정확도가 아닙니다.

모루/구슬/장식/UI 등 유닛이 없는 17개 crop도 전부 거부했습니다. 전체 경기 오탐이 없다는 의미는 아닙니다.

저장 51라운드를 현재 코드로 재분석해 연결/실행을 확인했습니다. 참조 작성에 사용한 이미지가 포함돼 있으므로 여기서 출력된 이름 개수는 정확도가 아닙니다. 원본 DB/이미지는 변경하지 않고 `capture-build/identity-v2-runtime/`에 저장했습니다.

이 단계는 56종을 언제나 인식하는 완성된 분류기가 아닙니다. 신경망 분류기를 켜거나 임계값을 계속 낮춰 이름을 억지로 채우지 않았습니다. 사용자의 요청대로 지금은 기존 자료로만 진행했습니다. 새로운 경기/스킨/자세에 대한 검증은 아직 없습니다.
